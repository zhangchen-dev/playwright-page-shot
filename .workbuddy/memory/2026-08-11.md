## 导出 HTML 命名不连续 + 第二步点击"没反应" 根因

**现象**：用户本地预览 `D:\shots-htmls\aaa-test` 录制的多模块/多主步骤页面，第二步点击跳转元素没反应；跳转逻辑指向 `step3`，但新增主步骤和模块后实际下一份页面被命名成 `step9`/`step12`，文件不存在。

**目录证据**：导出文件名为 `step1.html / step2.html / step9.html / step12.html`（按 demo_config 播放顺序应为 step1→step2→step9→step12，但 ID 不连续）。
每个 HTML 内嵌跳转脚本：
- step1: next=step2（唯一，正确）
- step2: 两条 → `nextStep="step3"`（陈旧、目标不存在）+ `nextStep="step9"`（正确）
- step9: 两条 → `nextStep="step10"`（陈旧）+ `nextStep="step12"`（正确）
- step12: 一条 → `nextStep="step13"`（目标不存在，末页本应无）

**根因（src 层，4 点）**：
1. 命名用 `recorder.js:889 _generateStepId` → `'step'+(++stepCount)`，`stepCount` 是**会话内只增不减的计数器**；新增主步骤/模块后 ID 出现缺口（step1/2/9/12）。`export.js:93` 直接写 `snapshot.htmlFile`，导出前**未做顺序重编号**（仅 re-record 路径调 `_renumberAllSteps`）。
2. 录制/重录会向同一页 htmlContent **追加多条** nav script；`_fixStepNavigationLinks`(`recorder.js:902`) 只处理匹配 `snapshot.nextStepId` 的那条，且当 `nextStepId` 已等于正确值时直接 `continue`(913) 跳过整页 → 陈旧脚本（step3/step10/step13）永不清理。
3. 替换用非全局 `split/join` 与无 `g` 的正则，只能改第一条 `var nextStep`，重复脚本清不干净。
4. 两种 nav script 风格不一致：html-capture.js `_buildNavScript` 用 `findElementById`（可搜 iframe 内元素），recorder.js:932 注入版只用 `document.getElementById`；若点击元素在 iframe 内，后者挂不上 handler，只剩陈旧 step3 脚本生效 → 404 没反应。

- 代码层修改方案（改 src）：
  ① 保存/导出前调用顺序重编号（复用/新增 `_renumberToSequential`），按 main→sub→step 扁平播放序赋 step1..N，改写 htmlFile/cssFile/iframeFiles/`<link>`/`<iframe src>`/nav 脚本/config URL；且**普通导出路径也要调用**（不只 re-record）。

  ③ next 链接按**扁平序列**计算（参考 `_fixStepNavigationLinks:903-912` 的 allStepsOrdered），跨子模块连续，不在子模块边界断链。

**口诀**：导出命名必须按播放顺序重排为无缺口 step1..N；每页 nav script 全局清空后只留一条；元素查找统一 iframe 感知。
