## 录制数据「打包出去还在」的原因（诊断）
- 用户疑问：打包出去运行发现之前的录制还在，是打包进去了还是共用目录？
- 结论：**不是打包进去了，是共用同一个目录**。
  - 打包 `files` 只含 `main/renderer/src/package.json` + Chromium(`extraResources`)，录制数据在 `app.getPath('userData')/recordings`（`C:\Users\123\AppData\Roaming\playwright-page-shot\recordings`），位于 AppData，不在安装包内。
  - `userData` 目录名 = `app.getName()` = `package.json` 的 `name` 字段（`playwright-page-shot`）。`productName`(场景录制助手) 只影响 exe 文件名/显示名，不改 `name`；打包时原样把同个 package.json 打进去 → 开发版(`electron .`)与打包版(`scene-recorder.exe`)都解析到同一个 `Roaming\playwright-page-shot` → 共用 `recordings`。
  - 证据：Roaming 下只有 `playwright-page-shot` 一个目录，没有 `scene-recorder`/`场景录制助手`；里面就是开发时录的 `123qqq-p1Vo`、`1qeZ36s`、`gongwen-123`、`hahh-G7sM`、`ssss`。
  - 实际影响：仅因在本机同时跑开发版和打包版(同一 Windows 账号)才"看得见"；分发给别的电脑/账号的打包版首次打开时该目录是空的，不会泄露你的数据。
  - 若想让打包版有独立干净的产品名存储：`package.json` 的 `name` 需改成 `scene-recorder`(或让 userData 按 productName 计算)，但这样开发版与打包版各用各的目录，旧数据在 `playwright-page-shot` 需手动迁移。
