## 修复：保存 dev/prd 后本地预览 CSS 丢失
- 根因：上一版 `_applyAbsoluteResourceUrls` 在保存时把 CSS `<link href>` 写死为带域名绝对地址；应用预览是 `file://` 加载本地 HTML（`renderer/modules/preview/preview.js` 的 `filePathToUrl` → `file://...`），浏览器请求不到绝对地址 → CSS 丢失。
- 改法：改为「运行时判定」（`src/recorder.js` 新增 `_applyRuntimeResourceUrls`）：dev/prd 保存时把 `<link rel="stylesheet" href="./stepX.css">` 替换为一段 `document.write` 脚本，运行时按 `window.location.protocol === 'file:'` 决定用相对 `./stepX.css`（本地预览）还是 `originName + stepX.css`（部署）。与 nextStep 导航脚本已有逻辑一致。
- 注意：iframe 的 `src` 保持相对（同目录，file:// 与 https 均解析正确），不再改写为绝对，避免破坏预览。
- 本地（local）保存：CSS 链接保持相对 `<link>`，不做处理。
- `sync-to-prd`（recording-mgmt-ipc.js）仍用 `oldOrigin→newOrigin` 字符串替换，可覆盖新 loader 内嵌的 origin 字面量；已同步修正该处注释。
- 验证：node --check 通过；逻辑单测确认 DEV 产物在 file:// 解析为 `./step1.css`、https 解析为带域名绝对地址，本地保持相对，iframe src 仍为相对。
