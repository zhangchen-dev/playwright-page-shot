# 2026-08-21 工作日志

## 修复：继续录制后第一步变空白/不可预览（根因：导航脚本移除正则误吞 body）
- 现象：用户把 `sen_code_KPsGmg` 同步生产得到 `sen_code_KPsGmg_prd_copy`，在副本上"继续录制"保存后，副本 step1 由 284KB 变成 2340 字节、缺失 `<body>` 开标签、正文全丢，无法预览；原始 KPsGmg step1 正常。用户强调"不是开始就坏的"。
- 根因：`src/recorder.js` `_sequentialRenumber` 第三遍的导航脚本移除正则
  `/<script>\s*\(function\(\)\s*\{[\s\S]*?var nextStep = "[^"]*";[\s\S]*?\}\)\(\);\s*<\/script>/g`
  会从页面自身的 `<script>(function(){var __R_ORIGIN__=…` 加载器（位于本脚本之前）惰性匹配到本录制器注入脚本里的 `var nextStep`，把其间整个 `<body>` 正文删掉。仅当**重新保存既有数据**（继续录制/重录）时触发——首次捕获保存不触发，所以"第一步原本正常、继续录制后坏了"。
- 修复：正则改为锚定本录制器脚本特征 `<script>\s*\(function\(\)\s*\{[^<]*?var elementIds\s*=\s*\[…`，要求 `<script>(function(){` 后紧跟 `var elementIds` 且中间无 `<`，精确只删本脚本。已用真实数据验证：原 284KB step1 移除后仍为 283KB、body 完整。
- 数据修复：副本 step1 结构与原始完全一致（同 stepId/nextStepId/elementIds），仅 htmlContent 损坏，已从原始 `sen_code_KPsGmg` step1 整体恢复（284148 字节、body 完整），step2/step3 保留；备份 `recording_data.json.repaired-*.bak`。
- 注意：用户仍需**重新构建/重启应用**（`npm run build:win` 或 `npm start`）使源码修复生效，否则继续用旧 asar 仍会复现。
