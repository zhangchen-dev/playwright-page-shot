## v21：修复 v20 引入的「连续进入移动端步骤底部超出」回归
- 用户反馈：v20 修复后，连续步骤进入移动端仍有「底部超出」。手动 resize 后刷新就好。
- **根因分析**：
  1. v20 FIT_SCRIPT 用**父容器** `iframeContent.clientWidth/Height`（壳子 422×852）算 scale，但 iframe 实际设计尺寸是 375×736（handleMobileResize 设的）。当内容宽高比偏向纵向时，按壳子尺寸算出来的 scale 让视觉高度接近 852，超过 iframe 设计高度 736，视觉上 iframe 装不下（虽然壳子 overflow:hidden 会裁剪，但 transform 变换后 iframe 元素之外的部分对 iframe 自身的 overflow:hidden 失效）
  2. PC 步骤遗留的 `iframe.style.transform` 在切到移动端时未被清除，60ms 延迟期间移动端内容被错误缩放
  3. iframe load 事件不一定在步骤切换时及时触发（缓存、相同 URL 等）
- **修复**：
  - `src/map-preview.js` FIT_SCRIPT 移动端分支：**改用 iframe 元素自身的 `iframe.clientWidth/clientHeight`** 作为目标算 scale；**不再覆盖 iframe.style.width/height**（让 handleMobileResize 设置生效），只通过 `transform: scale` 做视觉缩放。这样无论内容宽高比如何，视觉都完整装入 iframe bounds（375×736）
  - `src/map-template/app.js` `handleMobileResize` 非移动端分支：加 `iframe.style.transform = ''` 清除残留 transform
  - `src/map-template/app.js` `updateIframeUrl`：src 改变后派发 `window.dispatchEvent(new CustomEvent('map-step-changed'))`
  - `src/map-preview.js` FIT_SCRIPT 增加 `window.addEventListener('map-step-changed', () => setTimeout(fitDemoIframe, 30))` —— 步骤切换时立即重新计算（不等 iframe load）
- `MAP_PREVIEW_VERSION` 升 `'21'` 强制重建缓存
