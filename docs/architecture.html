playwright-page-shot · 系统架构图

基于 Electron + 应用内 webview 的网页录制桌面工具 —— 捕获页面快照、标记元素、多步骤导出与地图预览

01整体分层架构

经典 Electron 三层：主进程（业务内核）↔ Preload（安全桥）↔ 渲染进程（UI）。录制内核 src/ 运行在主进程，渲染层以 ES Module 直载、无打包步骤。

02模块全景与职责

按"内核 / 通信 / UI / 资源"四类梳理关键文件及其责任边界。

main/main.js

应用入口

  • 创建 1366×768 面板窗口（居中、可最大化）
  • 系统托盘 + 关闭最小化到托盘
  • webview setWindowOpenHandler 拦截 _blank → 多 tab
  • 实例化 Recorder / CredentialStore，注册 IPC
src/recorder.js

录制状态机

  • phase：config → recording
  • 维护 mainModules→subModules→steps 模块树
  • 场景码 / 环境 / 移动端 / 重录模式状态
  • handleAction 统一动作分发
src/html-capture.js

HTML 捕获引擎

  • page.evaluate 克隆 DOM 并清理录制面板/脚本/事件
  • cheerio 处理 CSS URL 与去重
  • 注入 autouse 气泡 SDK
src/export.js

导出器

  • 输出静态 HTML/CSS + demo_config.json
  • recording_data.json 隔离至 recording-meta
  • 兼容旧版路径回退
src/map-preview.js

地图预览

  • 复制 map-template 到 os.tmpdir（只读源）
  • transformData：按内容反推移动端 + subStep 级判定
  • FIT_SCRIPT 守卫式等比缩放
src/inject/*

webview 注入

  • element-helper：元素拾取高亮
  • credential-helper：凭证自动填充
  • webview-preload：webview 预加载桥
main/ipc/*

IPC 处理器

  • recorder / window / webview / credential
  • recording-mgmt（删除/下载/上传/同步/继续/重录）
  • preview（导出预览 / HTML 预览 / 地图预览）
renderer/modules

渲染层 UI

  • recording-ui：最大 UI 模块（表单/步骤/场景故事）
  • webview-recording：应用内录制编排
  • preview / management / demo / settings 视图

05数据模型层级

录制状态的单一真相源结构（Recorder.mainModules 树）。

sceneConfig { sceneTitle, sceneSubTitle, sceneName, sceneCode, environment, envBaseUrl } │ └─ mainModules[] // 主模块（"地图-场景"） ├─ subModules[] // 子模块（步骤分组） │ └─ steps[] // 具体步骤 │ ├─ stepId // step1..N 唯一连续 │ ├─ mainTitle / subTitle │ ├─ htmlContent // 捕获快照 + autouse SDK │ ├─ marks[] // 标记元素 │ ├─ selector.isMobileGuide // subStep 级移动端判定 │ └─ introduction // 场景故事主/副标 └─ introduction.isMobileGuide // 父级回退
判定规则：内容反推（viewport meta） › subStep.selector.isMobileGuide › 场景级 isMobileMode。每个 subStep 独立计算，解决同一 subModule 内 PC/移动混合。

06持久化与存储目录

08前后端交互模型

应用没有传统 HTTP 后端服务：所谓"前端"是渲染进程 UI，"后端"是主进程内核，二者仅通过 IPC（进程间通信） 桥接。唯一的"远端服务"是录制产物在回放/预览时才会访问的资源托管主机与 SDK CDN。

① 进程内：渲染进程 ⇄ 主进程（IPC 通道）

通道 / 方向用途
recorder-action
render→main		统一录制动作 → recorder.handleAction
stateSync
main→render(推送)		状态变更主动推给 UI 重渲染
get-inject-script → elementSelected取注入脚本 → webview 拾取 → 回传选择结果
get/save/delete-credential凭证加解密读写（safeStorage）
get-recorded-exports / delete / download / upload / sync-to-prd / continue / rerecord / reload场景管理与元数据回载
preview-export / preview-html-file / generate-map-preview本地预览与地图预览
get-webview-preload-path / sync-cookies-*webview 注入与登录态保持
renderer-log render→main渲染进程日志桥（终端可见）

② 远端服务依赖（仅回放/预览时触发）

导出 HTML 运行时加载 ├─ 资源主机 (originName) │ dev/prd: xft-service-marketing.paas.cmbchina.cn │ /resource/file/demonstration/<sceneCode>/ │ → 加载 CSS / iframe 内容 ├─ 气泡 SDK (autouse) │ xft-demo.cmburl.cn/helpapp/plugin/xft_help_autouse.js │ → 录制 HTML 自带，平台据此渲染指引气泡 ├─ sync-to-prd: 本地复制 + 改写 origin(dev→prd) │ 生成 <dir>_prd_copy（不推送服务器） └─ upload-recording: 占位 (TODO) 资源接口 / 配置接口地址待定，未真正实现
🔌 即开即用的"前后端"全在本地进程内完成；远端主机只承载最终产物的静态资源分发，不参与录制控制流。

09数据存储与取用（读写全链路）

数据分两类：导出产物（给用户/平台消费）与 内部元数据（支撑继续录制/重录/地图预览）。二者目录隔离；所有读写走主进程文件系统，渲染层通过 IPC 间接调用。
